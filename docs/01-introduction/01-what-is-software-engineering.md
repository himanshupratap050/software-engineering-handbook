## 1. Exam-Ready Definition
**Software Engineering** is the systematic, disciplined and measurable approach to developing, operating and maintaining software so that a quality product is delivered within time and budget.
**Software** is not just code: it is *programs + data structures + documentation*.

## 2. Core Concept
A small program can be written by one person in a day. A large system (a university ERP, a banking app) needs many people, many months, changing requirements and long-term maintenance. Without a disciplined approach it fails: late delivery, cost overrun, bugs. Software engineering provides the *process, methods and tools* to control this.

**Example:** For a *Library Management System* you do not start coding on day one. You first gather requirements, plan, design, then code, test, deploy and maintain. That ordered, controlled way of working is software engineering.

**Software Engineering as a layered technology**

| Layer | Meaning | Example |
|---|---|---|
| Quality focus (base) | Commitment to continuous improvement and quality | Total quality management mindset, SQA |
| Process | Framework of activities that holds the layers together; defines *what* to do and *when* | Waterfall, Spiral, Scrum |
| Methods | Technical *how-to* for tasks | Requirements analysis, DFD, design, testing techniques |
| Tools | Automated support for process and methods | CASE tools, IDE, Git, test tools |

## 4. Advantages, Disadvantages and Comparisons

| Benefits of applying SE | Limitations / challenges |
|---|---|
| Better quality and reliability | Needs training and discipline |
| Predictable cost and schedule | Process overhead for very small projects |
| Easier maintenance | Hard to estimate accurately |
| Better teamwork and documentation | Requirements keep changing |

**Program vs Software product**

| Program | Software product |
|---|---|
| Written for personal use, usually by one person | Built for many users, by a team |
| Little or no documentation | Full documentation (SRS, design, test, user manual) |
| Informal testing | Systematic testing and quality assurance |
| Not designed for maintenance | Designed to be maintained and enhanced |

## 5. Key Points for Revision
- Software = programs + data + documentation.
- SE = systematic, disciplined, measurable approach (development, operation, maintenance).
- Layers: Quality focus -> Process -> Methods -> Tools.
- Process is the glue of the layers; quality focus is the foundation.
- SE is needed because of size, complexity, teamwork and change.

## 9. Common Exam Mistakes and Confusing Pairs
- Writing "software = only code". Always mention data and documentation.
- Mixing up **process** (what/when) with **method** (how) and **tool** (automation).
- Forgetting that quality focus is the *base* layer.
